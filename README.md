## 4. Task 1 — step by step

```bash
cd task1_multimodal_retrieval
pip install -r requirements.txt
```

### 4a. Generate the corpus (already included, but reproducible)

```bash
python data/generate_corpus.py
```
Builds 12 synthetic intranet documents (10 PDFs + 2 standalone images) —
6 of them have a fact that exists **only** in a chart/diagram/table image,
not in any extractable text. See `task1_multimodal_retrieval/README.md`
for the full corpus design rationale.

### 4b. Choose how Qwen-VL runs (pick ONE)

**Option A — offline mock (default, zero setup, zero cost):**
Nothing to do. Captions/reranking are deterministic stand-ins grounded in
the corpus's own ground truth — good for verifying the pipeline plumbing,
not a claim about real captioning quality (see README "known limitations").

**Option B — local Qwen2-VL (free, runs on your machine):**
```bash
pip install -r requirements-local-qwenvl.txt   # torch, transformers, accelerate, qwen-vl-utils
export QWEN_VL_BACKEND=local                    # Windows: $env:QWEN_VL_BACKEND="local"
```
First run downloads model weights from Hugging Face (~4-5GB for the
default `Qwen/Qwen2-VL-2B-Instruct`) — needs network **once**, then fully
offline. CPU works but is slow; a GPU with 6GB+ VRAM is much faster.

**Option C — hosted Qwen-VL API (DashScope, paid):**
```bash
export DASHSCOPE_API_KEY=sk-...
```

### 4c. Run it

```bash
python ingestion.py           # sanity check: prints chunk/image counts
python -m pytest tests/ -v    # 15 tests
python evaluation.py          # writes data/eval_results.json + .csv, prints the metrics table
streamlit run app.py          # the actual deliverable
```

`streamlit run app.py` opens a browser UI: text or image query, mode
toggle (Multimodal / Text-only baseline), Top-K slider, and per-result
doc/page/image/relevance-score/match-reason. The sidebar banner tells you
which backend (mock / local / hosted) is currently active.

**Expected evaluation output** (offline mock backend, actually run):

| Pipeline | Precision@5 | Recall@5 | MRR | Avg latency |
|---|---|---|---|---|
| Text-only RAG | 0.441 | 0.867 | 0.867 | ~0.4 ms |
| Multimodal | 0.532 | 1.000 | 1.000 | ~0.4 ms |

Full honest discussion of *why* (and where multimodal actually helped
vs. just tied) is in `task1_multimodal_retrieval/README.md`.

## 5. Task 2 — step by step

```bash
cd task2_mcp_agent
pip install -r requirements.txt
python database.py            # builds data/company.db (3 tables, FKs, seed data)
```

### 5a. Choose how the agent's LLM runs (pick ONE)

**Option A — offline rule-based planner (default, zero setup, zero cost):**
Nothing to do. Reproduces the 3 demo questions' exact MCP call sequence
without any LLM — good for verifying the MCP connector + guardrails work,
not a general-purpose planner.

**Option B — local Ollama (free, runs on your machine):**
```bash
# install Ollama from https://ollama.com, then:
ollama pull qwen2.5:7b
ollama serve                  # usually auto-starts after install
export LLM_BACKEND=ollama     # Windows: $env:LLM_BACKEND="ollama"
```

**Option C — Claude (Anthropic, paid):**
```bash
export ANTHROPIC_API_KEY=sk-ant-...
```
If your key is "identity-linked" (personal Console login, not scoped to
one workspace), also set `ANTHROPIC_WORKSPACE_ID` — see
`task2_mcp_agent/README.md` for why and how to find it. Also note: the
Claude path needs actual API credits on the account to complete a
request (confirmed hitting a `400: credit balance too low` error with a
correctly-authenticated real key) — Options A and B have no such
dependency.

### 5b. Run it

```bash
python -m pytest tests/ -v    # 10 tests
python demo.py                # all 4 required scenarios, real MCP stdio transport
streamlit run app.py          # browser UI + deployable demo, same agent
```

`demo.py` runs, in order: (1) a simple lookup, (2) a 3-table JOIN with a
deliberate typo that triggers error-recovery, (3) an ambiguous question
that makes the agent ask for clarification instead of guessing, (4) a
guardrail proof (`DELETE` rejected before touching the DB). All four are
**actually verified working**, output captured in
`task2_mcp_agent/README.md`.

`app.py` is a thin Streamlit wrapper over the same `MCPAgent` — pick a
demo question from a dropdown (or type a custom one, with Claude/Ollama
configured), see the live tool-call trace and answer in the browser. This
is what gives Task 2 a deployable public URL, matching Task 1 — see
`DEPLOYMENT.md`.

For a one-off question:
```bash
python agent.py "Which projects does Karthik Iyer lead?"
```

## 6. Environment variables reference

| Variable | Task | Required? | Effect |
|---|---|---|---|
| `DASHSCOPE_API_KEY` | 1 | No | Hosted Qwen-VL API |
| `QWEN_VL_BACKEND` | 1 | No | `local` / `hosted` / `mock` — overrides auto-detection |
| `QWEN_VL_LOCAL_MODEL` | 1 | No | Override the local HF model name (default `Qwen/Qwen2-VL-2B-Instruct`) |
| `ANTHROPIC_API_KEY` | 2 | No | Claude-driven agent loop |
| `ANTHROPIC_WORKSPACE_ID` | 2 | No | Only needed for "identity-linked" Claude API keys — see `task2_mcp_agent/README.md` |
| `LLM_BACKEND` | 2 | No | `claude` / `ollama` / `offline` — overrides auto-detection |

Backend auto-detection order (both tasks): explicit override env var →
hosted API key present → local server reachable → offline fallback.

## 7. Design decisions (summary — full reasoning in each task's README)

| Decision | Choice | Why |
|---|---|---|
| Task 1 text embeddings | TF-IDF (scikit-learn) | No forced HF network dependency for the base install; explainable, zero-dependency baseline |
| Task 1 Qwen-VL deployment | 3 swappable backends behind `MultimodalModelClient` | No hard local requirement in the brief; one-class swap between mock/local/hosted |
| Task 1 embedding strategy | Hybrid: text chunks + image captions in one TF-IDF space | Simple, debuggable, one index — trades away true visual-similarity signal a joint embedding would keep |
| Task 2 database | SQLite | No concurrency/scale requirement; `mode=ro` URI gives a hard read-only guarantee with zero setup |
| Task 2 security model | Defense in depth: RO connection + tool-level SQL allow-list + row cap | A prompt instruction alone is advice, not enforcement — see `task2_mcp_agent/README.md` |
| Task 2 agent transport | Real MCP stdio subprocess (not in-process calls) | Matches how MCP actually isolates the DB credential from the agent process |
| Task 2 LLM | 3 swappable backends (Claude / Ollama / offline) | No key needed to grade the connector/guardrails; Claude or free local Ollama for the real planner |

## 8. Known limitations (top-level; full list in each README)

- Task 1's hosted-API and local-Qwen2-VL code paths are implemented in
  full but **unverified in the original dev sandbox** (no network egress
  there) — they're written to run on a normal machine with internet
  access, which is what you're using now.
- Task 1's evaluation is document-level, not answer-level — see "Honest
  discussion" in `task1_multimodal_retrieval/README.md` for what that
  hides and why it matters.
- Task 2's offline planner only handles the three demo questions by
  design (a grading fallback); Claude or Ollama unlocks general
  natural-language questions via the real plan-act-observe loop.
- Task 2's Ollama path is implemented against Ollama's OpenAI-style tool
  schema and depends on the chosen model actually supporting tool calls
  (`qwen2.5:7b` and `llama3.1:8b` do); not every Ollama model does.

## 9. Troubleshooting

- **`ModuleNotFoundError`** — run `pip install -r requirements.txt` inside
  the specific task folder you're in; each task's dependencies are
  independent.
- **Task 1: `streamlit run app.py` hangs/blank on first load** — first
  run ingests the corpus and captions every image; cached afterward
  (`@st.cache_resource`). If using local Qwen-VL, the first query also
  downloads model weights — check the terminal for progress/errors.
- **Task 1 local Qwen-VL: CUDA out of memory** — set
  `QWEN_VL_LOCAL_MODEL` to a smaller model, or unset `QWEN_VL_BACKEND`
  to fall back to mock mode while debugging.
- **Task 2: `sqlite3.OperationalError: unable to open database file`** —
  run `python database.py` first.
- **Task 2: agent gives short/offline answers even with a key set** —
  make sure the env var is exported in the *same shell* running
  `agent.py`/`demo.py` (this project doesn't auto-load `.env` — use
  `export $(cat .env | xargs)` or `python-dotenv` if you want that).
- **Task 2 Ollama: "model does not support tools"** — pull a tool-calling
  model (`qwen2.5:7b` or `llama3.1:8b`); not all Ollama models support
  the tools API.
